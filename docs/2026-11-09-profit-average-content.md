## 바꾼 것

- **제목**: `주식 수익률 계산기 | 수익률·평가 손익 계산`, `주식 평단가 계산기 | 물타기·불타기 평균단가 계산` (사이트 이름은 템플릿으로 뒤에 붙음).
- **설명**: 실제 입력·출력과 제외 범위를 그대로 적었다. 수익률은 수수료·세금·환율 미반영, 평단가는 최대 10회 입력·수수료 미반영.
- **중복 제거**: 두 페이지 모두 위쪽 설명 카드와 아래쪽 ‘더 알아보기’(SeoContent) 블록에 소개·공식·예시가 두 번씩 있었다. ‘더 알아보기’ 블록을 빼고 설명 카드 하나로 합쳤다. 공식은 페이지당 2회 → 1회. SeoContent 컴포넌트와 이를 쓰는 다른 8개 페이지는 그대로다.
- **검산 가능한 사례 추가**
  - 수익률: “증권사 앱 수익률과 계산기 결과가 다른 이유” — ① 첫 매수가 대신 평균 단가를 넣어야 하는 경우(−5.00% vs +5.56%) ② 수수료(0.015% **가정값**으로 997,750원·약 14.25%, 세금 제외) ③ 가격 시점 차이.
  - 평단가: “물타기하면 평단가는 낮아지는데 손실금은 왜 그대로일까?”(−20,000원 유지, 수익률 −20.00% → −11.11%, 본전 상승률 +25.00% → +12.50%, 7,000원 하락 시 −30,000원 vs −40,000원), “불타기하면 수익금은 그대로인데 수익률은 왜 낮아질까?”(+20,000원 유지, +20.00% → +9.09%), 사용 방법.
- **FAQ**: 수익률 FAQ를 실제 기능에 맞게 고쳤다(수수료·세금 미포함, 여러 번 산 경우 평균 단가 입력). 평단가 FAQ 답변을 사례와 맞췄다.
- **FAQ 보완(같은 날 후속 커밋)**: 평단가 FAQ의 “손실금은 줄지 않는다”에 성립 조건을 밝혔다 — 현재가와 같은 가격에 추가 매수한 직후, 수수료 제외. 검산: 10,000원×10주·현재가 8,000원 → −20,000원, 8,000원×10주 추가·현재가 그대로 → −20,000원, 추가 매수가 7,000원·현재가 8,000원 입력 → 평단가 8,500원·−10,000원(입력상의 반례이며 실제 체결 가능성을 뜻하지 않음). 세 사례는 실제 계산기 화면에 넣어 확인했다. 화면 FAQ와 JSON-LD는 같은 답변을 쓴다.

## 숫자 정합성 강제

- 본문 숫자는 `src/data/stockCalculatorExamples.ts`에서만 가져온다.
- `tests/stockCalculatorExamples.test.ts`가 같은 입력을 실제 계산기 화면에 넣어 결과 문자열을 대조한다. 숫자를 바꾸면 테스트가 실패한다. 수수료 가정 예시는 정수 산술로 따로 계산한다. 렌더링 결과에 ‘더 알아보기’ 블록이 다시 생기면 실패한다.
- 숫자는 Python Fraction으로도 별도 계산해 같은 값임을 확인했다.

## 확인하지 않은 것

- 수수료율 0.015%는 설명용 가정이다. 특정 증권사의 실제 수수료율이나 앱의 수익률 표시 방식(수수료·세금 반영 여부)은 확인하지 않았고, 본문도 “증권사·설정에 따라 다르다”로만 적었다.
- 네이버 검색 지침·블로그 노출 관련 주장은 이 변경의 근거로 쓰지 않았고 별도로 확인하지 않았다.

### 비교 방법

- 서치어드바이저에서 비교할 지표는 노출·클릭·CTR이다. 평균 게재순위는 이 비교 지표에 넣지 않는다.
- 운영 반영일 이후 2~4주 단위로, 기준선과 같은 기간 길이로 페이지별 지표를 비교한다. 며칠 단위 등락으로 판단하지 않는다.
- 실제 네이버 유입 방문과 블로그 경유 방문은 서치어드바이저 지표와 따로 본다.
- 검색 위치를 추적한다면 서치어드바이저 지표와 구분한 별도 관찰 기록으로 남긴다. 검색어·기기·로그인 여부·확인 시점을 고정해 같은 조건에서만 비교한다.
