## 1. 전체 요약

**핵심 수식은 건강합니다.** 18개 계산기의 계산식을 소스에서 추출해 Python `Decimal`(정밀도 50자리)로 독립 검산한 결과, 표시 반올림을 제외한 **수학적 계산 오류는 0건**이었습니다. 손익비의 손익분기 승률 `W = 1/(1+R)`, 본전 회복률 `L/(1−L)`, 포지션 사이즈의 `Math.floor` 정수 처리, 복리의 0% 분기 NaN 회피까지 모두 정확합니다.

문제는 다른 세 곳에 몰려 있습니다.

1. **입력 검증과 경계 처리** — 음수·빈칸·비현실적 값이 조용히 통과해 존재할 수 없는 결과(음수 손절가, 자본금의 10배 포지션)를 정상값처럼 출력합니다.
2. **메타데이터 배선** — 13개 페이지가 홈으로 canonical 되어 있어 색인에서 통째로 빠져 있을 수 있습니다.
3. **YMYL 신뢰 요소** — 세율·공제액을 단정적으로 제시하면서 기준일과 출처 링크가 사이트 전체에 **0건**입니다.

> **한 줄 판단** — AdSense 재심사·색인 개선을 노린다면 **canonical 13페이지**와 **계산기 3종의 입력 검증**이 먼저입니다. 이 둘은 각각 반나절 안에 끝나고, 나머지 항목보다 효과가 훨씬 큽니다.

## 2. 배포·운영에 치명적인 문제 (P0)

세 건 모두 **라이브 사이트에서 직접 재현**했습니다.

### P0-1. 계산기·허브 13개 페이지의 canonical이 홈을 가리킴

`src/lib/calculatorPages.ts`의 `metadata` 객체에 `alternates`가 없고, 해당 페이지들이 이 객체를 `export const metadata = config.metadata`로 그대로 내보냅니다. Next.js App Router는 자식이 정의하지 않은 필드를 부모 레이아웃에서 상속하므로, `layout.tsx`의 `alternates.canonical: "https://주식계산기.kr"`가 13개 페이지에 그대로 적용됩니다.

```
fetch('/crypto/entry')      → <link rel="canonical" href="https://xn--989a00a691bv6b3zl.kr/">   ← 홈
fetch('/profit-calculator') → …/profit-calculator                                              ← 정상(buildMetadata)
```

해당 13개: `/compound-interest-calculator`, `/overseas-stock-tax-calculator`, `/us-stocks/exchange-profit`, `/us-stocks/dividend`, `/crypto/entry`, `/crypto/liquidation`, `/crypto/leverage-profit`, `/crypto/profit`, `/crypto/funding-fee`, `/crypto/average`, `/stocks`, `/crypto`, `/us-stocks`.

**사이트 콘텐츠의 약 40%**가 여기 해당하며, 코인 카테고리는 전멸입니다.

**권장 수정** — 13개 페이지를 나머지 16개와 동일하게 `buildMetadata({ …, path: "/실제경로" })`로 통일. 한 번의 리팩터로 og:image 소실(6절), twitter 카드 홈 문구까지 같이 해결됩니다.

### P0-2. 포지션 사이즈 계산기가 자본금을 초과하는 매수를 "권장"함

```
/position-size-calculator · 자본금 10,000,000 / 리스크 2% / 진입 50,000 / 손절 49,900
→ 권장 매수 금액 100,000,000원 · 2,000주 · 총 자본 대비 비중 1000.0%
→ 안내문 "손절가 도달 시 계좌 총 손실액은 정확히 -200,000원(2%)으로 제한됩니다"
```

손절을 49,990으로 더 좁히면 **10억원 / 10,000%**가 나옵니다. "정확히"라는 표현도 사실이 아닙니다 — `Math.floor` 내림 때문에 실제 손실은 대개 표시액보다 작습니다(예: 손절 47,000 → 66주 → 실제 198,000원).

**권장 수정**
- 비중 > 100%이면 "손절폭이 좁아 리스크 한도 내에서 이 수량을 매수할 수 없습니다" 경고 + 자본 제약 하 최대 수량 `floor(자본/진입가)` 병기
- "정확히"를 "최대 …이내"로, 실제 손실액은 `권장수량 × 주당손실`로 재계산
- 권장 수량 0주일 때 손실 한도 문구 숨김

### P0-3. 손절가 계산기만 입력 검증이 없어 음수 가격이 출력됨

9개 국내 계산기 중 `StopLossCalculator.tsx`만 `parsePositive()`를 쓰지 않고 `if (!buy || !qty || !stopPercent)`로 검사합니다. 0과 NaN만 걸러지고 **음수는 falsy가 아니므로 전부 통과**합니다.

```
/stop-loss-calculator · 50,000 / 10주 / 손절률 150%
→ 손절가 -25,000원 · 1주당 손실 75,000원 · 총 손실 비율 150.00%

/stop-loss-calculator · 50,000 / 10주 / 손절률 -5%
→ 손절가 52,500원(매수가보다 높음) · 1주당 손실 -2,500원
```

**권장 수정** — 다른 8개와 동일하게 `parsePositive`로 통일하고 `0 < 손절률 < 100` 범위 검증 추가. 필드별 오류 메시지 노출.

## 5. AdSense 승인 관점 위험 평가

Google 게시자 정책 기준의 **위험도 평가**입니다. 승인 여부는 Google 재량이므로 "승인 가능/불가"로 단정하지 않습니다.

### 승인 전 반드시 수정

| 항목 | 현재 상태 | 정책상 위험 |
|---|---|---|
| **YMYL 신뢰 요소 부재** | 세금·투자 콘텐츠 전편에 작성자·검토일·기준일·출처 링크 **0건**. Article JSON-LD에 날짜 필드 없음 | "신뢰할 수 없는 콘텐츠" 판정. 금융 주제 최다 거절 사유 |
| **계산 결과의 사실 오류** | 자본금 10배 매수 "권장", 음수 손절가 (2절 P0-2·P0-3) | 오해를 유발하는 금융 정보. 심사자가 값을 넣어볼 수 있는 항목 |

### 승인 가능성을 높이기 위해 권장

- **연락 수단의 실효성** — 문의 이메일이 `support@주식계산기.kr`로 **한글 도메인**입니다. 국제화 이메일(EAI)을 지원하지 않는 환경에서는 반송될 수 있어 ASCII 별칭 병기를 권합니다.
- **얇은 콘텐츠** — 계산기 SEO 본문이 공백 제외 **465~1,111자**. 최소인 `/compound-interest-calculator`(465자)와 `/overseas-stock-tax-calculator`(491자)는 예시 섹션조차 없습니다.
- **템플릿 균질성** — 계산기 10페이지가 동일 골격: `headerDescription`의 "…를 기준으로 …계산하는 도구입니다" 8/10, `articleTitle`이 "…란?" **10/10**, `formulaTitle`이 "… 계산 기본 개념" **10/10**. 가이드도 6/7편이 정확히 3섹션×2문단, 문장 종결 **178/178이 "~습니다"**.

### 승인 후 개선 가능

- 광고 배치 — 현재 `ins.adsbygoogle` 슬롯 **0개**, `<head>` 스크립트만 로드(자동 광고 전제). 계산기는 **결과 카드 주변 광고가 버튼 오인 위험**이 크므로 결과 영역을 제외 구역으로 지정 권장.
- 모바일 첫 화면이 입력 폼이므로 상단 앵커 광고는 입력 방해 소지.

### 문제 없음

- `ads.txt` 정상 (`google.com, pub-6405509957088169, DIRECT, f08c47fec0942fa0`)
- 정책 페이지 4종 존재, 푸터 전역 링크

- 저작권·출처 문제 없음, 빈 페이지·미완성 페이지 0개

- **P3** `formatNumber`가 코인 계산기 6개 파일에 복붙, `toPositive`는 `parsePositive`와 동일 구현. 비유한값 폴백이 `"0"`과 `"-"`로 갈리는 것이 3절 P1 오류의 직접 원인.

## 11. 수정 우선순위 로드맵

### 즉시 수정 — 반나절

- **canonical 13페이지** — `config.metadata` → `buildMetadata({..., path})` 일괄 교체. og:image·twitter 문제까지 동시 해결. *효과 대비 비용이 압도적으로 좋은 유일한 항목*
- **손절가 계산기 입력 검증** — `parsePositive` 전환 + 범위 검증. 파일 1개
- **포지션 사이즈 자본 상한 + "정확히" 문구** — 파일 1개
- **펀딩비 방향 부호** — 계산에 `positionType` 반영. 3줄
- **환율 효과 항목 분리** — `exchangeEffectKrw = 총매도USD × (매도환율 − 매수환율)`. 1줄
