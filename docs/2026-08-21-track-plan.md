### B. 투자 시뮬레이션 플랫폼 로드맵 (제품 확장의 본체)

**구현 순서** (2026-08-21 조정)

```
1. MonteCarloEngine
2. DCA
3. 목표달성확률      ← FIRE·SoRR 앞으로 이동
4. FIRE
5. SoRR
6. 무매도 리밸런싱
7. 포트폴리오

```

목표달성확률은 엔진 + DCA만 있으면 바로 검증 가능하다(`goal.kind = "terminal-target"` +
**선형 정확 역산** — 같은 난수 경로에서 종말자산이 납입액에 아핀이므로 재시뮬 없이 역산). 반면 FIRE·SoRR은 적립→인출 구간 연결과 소진 추적·성공확률을
함께 다뤄야 해서 구현 범위가 크다. 검증 가능한 단위를 먼저 붙이는 순서로 조정.

## MonteCarloEngine 설계 확정 사항

문서: `docs/2026-08-21-montecarlo-engine-contract.md`

| 항목 | 결정 |
|---|---|
| 수익률 생성 | `ReturnGenerator` 추상화. **충격 분포 기본 Student's t (df 6, 분산 보정 `sqrt((ν−2)/ν)`)**, 정규/로그정규는 옵션. 부트스트랩은 나중에 교체 |
| 실행 환경 | 브라우저 Web Worker (서버 비용 0, 재무 데이터 외부 유출 없음, UI 논블로킹) |
| 입력 방식 | 자산배분 프리셋 + 직접 수정. **프리셋 숫자는 출처·`asOf` 노출 필수** |
| 시간 단위 | 월 스텝 고정 (DCA 월납·SoRR 월인출의 최소공배수) |
| 재현성 | 시드를 입력에 포함, 결과에 에코 |
| 성능 목표 | 10,000경로 × 480개월 데스크톱 1초 이내 |
| 목표 역산 | **선형 정확 역산 기본** — `c_j = (W*−A_j)/B_j` 의 **p 분위수**(1−p 아님). 이분 탐색은 선형성이 깨지는 구간(FIRE·SoRR·리밸런싱)에서만 폴백 |
| 드리프트 | **CAGR 기준** `μ_m = ln(1+CAGR)/12`. 중앙값 경로가 입력 CAGR로 정확히 복리. 산술평균→로그정규 변환은 쓰지 않음 |
| 1순위 회귀 테스트 | `volatility = 0`이면 기존 복리 계산기와 원 단위까지 일치 (t로 바꿔도 유지) |

착수 전 남은 결정 5건(프리셋 출처, 인플레이션 기본값, 세금 처리 위치, 결과 공유 방식,
`/lab` 데이터셋 라이선스)은 설계 문서 10절에 정리.

## 원칙 메모

- **글자 수는 품질 기준이 아니다.** 계산기 본문 "1,500자 이상" 같은 목표는 쓰지 않는다.
  필요한 설명만 충분히 쓴다 — 분량을 맞추려 늘리면 이미 지적된 템플릿성이 심해진다.
- **코인 가이드 클러스터**는 청산가·레버리지·펀딩비·코인 DCA·거래 수수료처럼 코인 계산기와
  직접 물리는 문서로 묶는다. 본전 회복·양도세·손익비는 별개의 주식 가이드 확장.
- **세법 숫자는 작성·개정 시점마다 1차 출처로 재확인.** 중앙화의 목적은 값 고정이 아니라
  수정 위치를 한 곳으로 모으는 것. `asOf`를 함께 둔다.
