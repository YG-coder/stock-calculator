## 2. 가정의 단위 — 포트폴리오가 1급 시민

### 문제

"자산별로 CAGR·σ를 입력받아 합성한다"는 설계는 자연스러워 보이지만, 합성 규칙에서 바로 막힌다.

```
포트폴리오 CAGR = Σ(w · cagr)      // 근사적으로 수용 가능
포트폴리오 σ    = Σ(w · σ)         // ← 상관계수 1을 가정하는 것과 같다
```

두 번째가 문제다. **단순 가중합은 분산효과가 0이라고 선언하는 것**과 같다. 실제 크기는 이렇다.

| 60/40 (주식 σ15%, 채권 σ5%) | 실제 σ | 단순 가중합 | 과대 |
|---|---|---|---|
| ρ = 0.0 | 9.22% | 11.00% | **+19.3%** |
| ρ = 0.2 | 9.60% | 11.00% | **+14.6%** |
| ρ = 0.5 | 10.15% | 11.00% | +8.4% |
| ρ = 1.0 | 11.00% | 11.00% | 0% |

캘리브레이션 오차를 2% 이내로 맞춰놓고 입력에서 15%를 틀리면 앞의 정밀도가 의미를 잃는다.

### 결정

**프리셋은 포트폴리오 수준의 `cagr`·`volatility`를 직접 들고 있는다.** 자산 구성은 화면 설명용 메타데이터이고 계산에 쓰지 않는다. `주식 60 / 채권 40` 프리셋의 σ는 두 자산 σ를 합성한 값이 아니라, **그 배분의 과거 실적에서 직접 구한 값**이다.

이렇게 하면

- 합성 규칙 자체가 필요 없다 — 분산효과는 이미 그 숫자 안에 들어 있다
- 엔진 계약이 그대로다. `ReturnSpec`은 여전히 스칼라 두 개만 받는다
- 출처·기준일이 포트폴리오 단위로 하나만 붙는다

**커스텀 혼합**(사용자가 비중을 직접 조정)에서만 합성이 필요하다. 이때는 단순 가중합을 쓰되 화면에 명시한다.

> 자산을 직접 섞은 경우 변동성은 분산효과를 반영하지 않은 보수적 추정입니다.
> 실제 변동성은 이보다 낮을 수 있습니다.

과대추정은 **안전한 방향**이다. 목표달성확률에서 σ가 크면 필요 납입액이 더 크게 나온다. 낙관적으로 틀리는 것보다 낫다.

공분산 행렬(`σ² = wᵀΣw`)은 6단계 무매도 리밸런싱에서 도입한다. 그때는 상관계수가 계산의 본질이 되므로 피할 수 없지만, 지금 끌어오면 입력 UI와 출처 관리 부담만 늘어난다.

## 3. 인플레이션 — 이미 계약에 있다

제안된 A안/B안은 사실 같은 것의 두 표현이고, 엔진 계약은 이미 정해져 있다.

```
입력:   expectedReturn = 명목 CAGR,  inflationRate = 연 물가
진행:   명목으로 시뮬레이션
기록:   reportBasis === "real" 이면  balance / (1+π)^(m/12)
```

드리프트를 실질로 바꿔서 돌리는 방식과 **중앙값 경로는 동일**하다. 기록 시점 환산을 택한 이유는 명목·실질 토글이 재시뮬레이션 없이 즉시 전환되기 때문이다.

**진짜 잠가야 하는 건 입력 라벨이다.**

- `기대수익률 (연복리, 명목)` — 실질 수익률을 넣고 물가까지 입력하면 **이중 차감**된다
- `물가상승률` 기본값은 출처와 기준일을 붙인다. 값 없이 숫자만 박지 않는다

FIRE·SoRR에서 실질 기준이 필수라는 지적은 맞다. 그래서 **`reportBasis` 기본값을 `"real"`로 둔다** — 30년 뒤 명목 금액은 직관을 왜곡한다.

## 4. 현금흐름 — 부호 하나로 유지

제안된 형태는 `type: contribution | withdrawal` + `amount`인데, 계약은 부호 있는 스칼라다. **계약을 유지한다.**

이유는 FIRE다. 적립 20년 → 인출 30년을 한 스케줄로 표현해야 하는데, `type` 필드가 있으면 구간마다 타입이 바뀌고 부호와 타입이 이중으로 존재해 불일치가 생긴다. `monthlyAmount < 0`이면 인출, 그게 전부다.

```ts
// 유지
{ monthlyAmount: 1_000_000, timing: "end", inflationIndexed: true, fromMonth: 0, toMonth: 240 }
{ monthlyAmount: -3_000_000, timing: "start", inflationIndexed: true, fromMonth: 240 }
```

UI에서는 "적립/인출"로 보여주고 저장할 때 부호로 변환한다. **부호 변환은 한 곳(폼 → 입력 객체 매핑)에서만** 한다.

## 5. 목표 정의 — v1은 하나만

`GoalSpec.kind`는 계약에 셋을 열어두되 **v1에서 구현하는 것은 `terminal-target` 하나**다.

| kind | 단계 | 선형 역산 |
|---|---|---|
| `terminal-target` | **3단계 (v1)** | 가능 |
| `never-depleted` | 5단계 SoRR | 불가 (클램프) |
| `income-target` | 6단계 이후 | 불가 |

`income-target`("월 300만원 현금흐름")은 실질적으로 인출 스케줄 역산이라 클램프가 개입한다. 타입만 예약하고 구현은 미룬다.

## 6. 표시 백분위 — 화면과 결과 객체를 분리

두 문서가 어긋나 있었다. 계약은 `p5/p25/p50/p75/p95`, 이후 논의는 `10/25/50/75/90`. **분리해서 잠근다.**

- **결과 객체**(`PercentileBand`, `Distribution`): p5·p10·p25·p50·p75·p90·p95 전부 보관
- **화면 기본 표시**: **10 / 25 / 50 / 75 / 90**
- p5·p95는 "더 넓게 보기" 토글이나 툴팁에서만

10,000경로에서 p5는 500번째 값 근처라 통계적으로는 안정적이다. 화면에서 빼는 이유는 정밀도가 아니라 **해석 부담**이다. 극단 밴드를 기본으로 보여주면 사용자가 그 폭을 "일어날 범위"로 읽는다.

```
10년 후 예상 자산 (실질 기준)

  10%  4,200만원
  25%  6,100만원
  50%  8,900만원      ← 강조
  75%  1억 2,700만원
  90%  1억 8,000만원
```

**중앙값만 진하게.** 평균은 표에도 넣지 않는다(t 꼬리에서 불안정).

## 7. v1 제외 항목 — 배당은 "제외"가 아니다

❌ 세금 · 거래비용 · 환율 · 리밸런싱 — 전부 상태 의존을 만들어 선형 역산을 깬다. 결과 카드에 미반영을 명시한다.

**배당은 다르다.** 프리셋의 CAGR을 **총수익(total return) 기준**으로 정의하면 배당 재투자는 이미 그 숫자 안에 들어 있다. "배당 미반영"이라고 쓰면 오히려 틀린 안내가 된다. 문구는 이렇게 간다.

> 수익률은 배당을 재투자한 총수익 기준입니다. 세금과 거래비용은 반영하지 않았습니다.

프리셋 정의에 `returnBasis: "total-return"`을 명시적으로 남겨, 나중에 가격지수 기반 수치가 섞여 들어오는 것을 막는다.

## 8. 프리셋 구조

```ts
export interface PortfolioPreset {
  id: string;                    // "global-equity-100"
  label: string;                 // "글로벌 주식 100%"
  summary: string;               // 한 줄 설명

  /** 엔진이 직접 쓰는 값 — 포트폴리오 수준 */
  cagr: number;                  // 명목 CAGR (총수익 기준)
  volatility: number;            // 연 σ, 단순수익률 기준
  returnBasis: "total-return";   // v1은 이 값만 허용

  /** 표시용. 계산에 사용하지 않는다 */
  composition: { label: string; weight: number }[];

  /** 신뢰 요소 — 하나라도 없으면 프리셋을 만들지 않는다 */
  source: {
    label: string;               // 지수·기관명
    url?: string;
    period: string;              // "1994–2025" — 어느 구간의 실적인가
  };
  asOf: string;                  // YYYY-MM-DD

  caveat?: string;               // 이 프리셋 고유의 한계
}
```

### 프리셋 목록 (v1 후보)

| id | label | 구성 | 비고 |
|---|---|---|---|
| `global-equity-100` | 글로벌 주식 100% | 주식 100 | 변동성 가장 큼 |
| `equity-60-bond-40` | 주식 60 / 채권 40 | 주식 60, 채권 40 | 가장 널리 쓰이는 기준 배분 |
| `equity-40-bond-60` | 주식 40 / 채권 60 | 주식 40, 채권 60 | 보수적 |
| `custom` | 직접 입력 | — | 프리셋 없이 값만 입력 |

**"올웨더"는 v1에서 제외한다.** 특정 운용사의 전략명이라 ① 수치 출처를 그 전략의 실적으로 특정해야 하고 ② 이름을 쓰는 순간 그 전략을 추천하는 것으로 읽힌다. 일반명(위험균형 배분)으로 바꾸더라도 출처가 확보되기 전에는 넣지 않는다.

### 출처가 없으면 프리셋을 만들지 않는다

이게 가장 중요한 규칙이다. 감사에서 사이트 전체의 기준일·출처가 0건이었고, 새 기능에서 같은 결함을 반복하지 않기 위한 조건이다.

**출처 후보와 각각의 문제**

| 후보 | 장점 | 문제 |
|---|---|---|
| 주요 지수 장기 실적 | 검증 가능, 널리 통용 | 지수 데이터 인용 범위 확인 필요 |
| 기관 장기 기대수익률(CMA) | 미래 지향적, 출처 명확 | 기관마다 편차가 크고 매년 갱신 |
| 국내 통계 | 국내 사용자에게 적합 | 장기 시계열이 짧고 구성이 다름 |

**착수 판단**: 출처 확보가 늦어지면 **프리셋 없이 "직접 입력"만으로 v1을 낸다.** 프리셋은 편의 기능이고, 출처 없는 숫자를 기본값으로 노출하는 쪽이 훨씬 큰 리스크다. 화면에는 참고용 범위를 문장으로만 제시한다("장기 주식 투자의 연 변동성은 통상 15~20% 수준입니다" — 이 문장에도 출처를 붙인다).

### 프리셋 → 커스텀 전환

기존 `DividendCalculator`의 `taxRateTouched` 패턴을 그대로 따른다. 사용자가 프리셋을 고른 뒤 값을 수정하면 프리셋 선택은 `custom`으로 바뀌고, **수정한 값은 다른 프리셋을 다시 고르기 전까지 유지**된다.

```
프리셋 선택 → cagr·volatility 채움 → 사용자가 수정 → id = "custom", 출처 표기 제거
```

출처 표기를 지우는 것이 중요하다. 사용자가 바꾼 숫자에 기관 출처가 붙어 있으면 잘못된 신뢰를 준다.

### 입력 범위 검증

캘리브레이션 테이블이 `σ_m ∈ [0, 0.15]`를 덮으므로 입력 σ의 상한이 정해진다.

| CAGR | 커버 가능한 입력 σ 최대 |
|---|---|
| 0% | 약 47.7% |
| 7% | 약 51.0% |
| 15% | 약 54.8% |

**입력 제한**: `cagr ∈ [−0.5, 0.5]`, `volatility ∈ [0, 0.45]`. 상한을 테이블 한계보다 낮게 잡아 여유를 둔다. 범위를 넘으면 조용히 클램프하지 말고 **입력 오류로 표시**한다 — 기존 계산기 감사에서 지적된 "음수를 조용히 0으로 치환" 패턴을 반복하지 않는다.

## 9. 이 문서로 확정되는 입력 계층

```
[프리셋 선택 또는 직접 입력]
        │  cagr (명목, 총수익)  ·  volatility (단순수익률 기준)
        ▼
   returns.ts  ── 캘리브레이션 테이블 역보간 ──▶  μ_m, σ_m
        ▼
   ReturnSpec { kind: "parametric", expectedReturn, volatility, shock: t(6) }
        ▼
   SimulationInput { …, cashFlow(부호 있는 스칼라), inflationRate, reportBasis: "real" }
        ▼
   MonteCarloEngine
```

**엔진 계약은 이 문서로 바뀌지 않는다.** 전부 입력 계층에서 흡수된다 — 계약을 먼저 잠근 값어치가 여기서도 확인된다.

## 10. 남은 결정

1. **프리셋 수치의 출처** — 확보 전까지 프리셋 없이 출시. 이 결정이 v1 착수를 막지는 않는다
2. **물가상승률 기본값**과 그 출처·기준일
3. 결과 공유 방식 — URL 직렬화는 개인 재무 정보 노출로 권하지 않음. 로컬 저장 우선
