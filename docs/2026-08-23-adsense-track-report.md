## 1. 수정한 핵심 내용

### ① 커스텀 404 페이지 신설
기존에는 Next.js 기본 404였다. 많이 찾는 계산기 5개 + 전체 메뉴 + 문의 안내를 담은 페이지를 만들었다. HTTP 상태는 정상적으로 **404**를 반환한다.

### ② 정책 페이지에 시행일·최종 개정일 표기
`/privacy`, `/terms` 모두 날짜 표기가 **0건**이었다. 두 페이지 상단에 시행일과 최종 개정일을 넣었다.

### ③ 광고·데이터 처리 고지 보강
개인정보처리방침에 이미 "광고 서비스 이용" 항목이 있었으나 실링크와 거부 방법이 없었다.

- Google 및 제3자 광고 사업자의 **쿠키 사용, 이전 방문 기반 광고 제공** 가능성 명시
- 거부 경로 4개를 실링크로: [Google 광고 설정](https://adssettings.google.com), [Google 광고 및 쿠키 안내](https://policies.google.com/technologies/ads), [aboutads.info](https://www.aboutads.info), 브라우저 설정
- **"5. 분석 도구" 항목 신설** — 소스 전체를 확인한 결과 애드센스 스크립트 외에 분석 도구가 없다. 사실대로 "별도의 웹 분석 도구를 사용하지 않는다"고 적고, 검색엔진 소유 확인 태그는 방문자 정보를 수집하지 않는다는 점을 구분해 기재했다.
- 계산 입력값이 **브라우저 안에서만 처리되고 서버로 전송되지 않는다**는 점을 명확히 했다.

> 기존 방침에는 "로컬 스토리지로 마지막 입력값을 저장할 수 있다"고 적혀 있었으나, 코드에는 `localStorage` 사용처가 **0건**이었다. 실제와 맞게 "현재는 보관하지 않으며, 향후 추가 시 기기에만 저장된다"로 고쳤다.

### ④ 세금 신뢰 요소 블록 신설
`SourceNote` 공용 컴포넌트를 만들어 세금이 개입하는 계산기 3개에 붙였다. 표시 항목은 적용 기준연도 · 최종 검토일 · 적용한 세율과 공제액 · 결과가 달라질 수 있는 조건 · 공식 출처 링크 · 작성 주체다.

작성 주체는 **"주식계산기.kr 운영자가 정리한 참고 자료이며 세무 자문이 아님"**으로 적었다. 실존하지 않는 검수자나 자격증은 만들지 않았다.

### ⑤ 세율 단일 소스화
`0.22`, `15.4`, `2500000`이 계산기 코드·SEO 문구·가이드 본문 등 **5곳 이상에 흩어져** 있었다. `src/lib/taxRates.ts`로 모으고 각 값에 `asOf`와 출처를 함께 담았다. 이제 제도가 바뀌면 한 곳만 고치면 된다.

### ⑥ 가이드 시제·조사 오류 수정
- 2026년 **시행 중**인 배당 분리과세 특례를 "도입되는"으로 미래형 서술한 2곳 → "시행되는"
- 세금 가이드 2편 도입부에 "2026년 8월 기준" 명시
- `compound-investing` FAQ 조사 오류 1건("정확한 공식은 아니라" → "정확한 공식이 아니라")

### 작업 중 되돌린 판단 하나

404의 `robots` 메타 태그를 중복으로 판단해 제거했더니, **루트 레이아웃의 `index, follow`를 상속받아 `noindex`와 `index, follow`가 함께 출력**됐습니다. 상충하는 신호라 더 나빴습니다. 명시 지정으로 되돌려 두 태그가 `noindex` / `noindex, follow`로 일치하게 했습니다. 태그가 두 개인 것은 Next가 not-found 응답에 자동으로 넣는 것이라 제거할 수 없습니다.

## 6. 자동으로 확인할 수 없었던 항목

- **국세청·법제처 딥링크의 생존 여부** — robots.txt 차단으로 확인 불가. 기관 루트 링크로 대체
- **실제 배포 환경(Cloudflare/OpenNext)에서의 404 동작** — 컨테이너의 `next start`에서만 확인했습니다. OpenNext는 정적 asset을 재배치하므로 `npm run preview`로 한 번 더 확인하시길 권합니다
- **실사용자 Core Web Vitals** — 코드 구조 기반 판단만 가능
- **애드센스 심사자의 판단 기준** — 정책 문서로 추정할 뿐입니다

## 7. Search Console에서 운영자가 직접 해야 할 작업

1. **sitemap 재제출** — 콘텐츠가 바뀐 페이지가 있으므로
2. **URL 검사 → 색인 요청** — `/privacy`, `/terms`, 세금 계산기 3개
3. **404 확인** — "페이지" 리포트에서 소프트 404가 잡히지 않는지
4. 지난번 canonical 수정분에 대해 **"대체 페이지(적절한 canonical 태그 포함)" 경고가 해소됐는지** 재확인
5. 애드센스 콘솔에서 **ads.txt 상태 정상** 확인
