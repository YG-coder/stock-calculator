# 코인 100배 진입 계산기 ↔ MJ 엑셀 대조 및 보완 (2026-08-21)

대상: `/crypto/entry` → `src/components/calculator/CryptoEntryCalculator.tsx`
원본: `MJ 진입 타점 계산기마스터 클래스.xlsx` (Sheet1)

## 대조 결과 — 핵심 수식은 100% 일치

| 항목 | 엑셀 | 코드 | 기본값 결과 |
|---|---|---|---|
| 손절폭 % | `(C2-C3)*100/C2` | `((entry-stop)/entry)*100` | 1% |
| 배율 | `C9 = 100/C5` | `100 / lossPercent` | 100배 |
| 리스크 금액 | `E8 = E6/20` (시드×5%) | `seed * risk/100` | 5 |
| 진입수량(명목가치) | `C7 = C9*E8` | `leverage * riskAmount` | 500 |
| 익절가 | `C4 = C2+(C2-C3)*1.5` | `entry + (entry-stop)*rr` | 10,150 |

기본값(10000 / 9900 / 시드 100 / 리스크 5% / 손익비 1.5)도 엑셀과 동일. **수식 오류 없음.**

## 이번에 추가한 것

1. **손익비별 목표가 표** (엑셀 E2:N3) — 1:1.1 ~ 1:10 목표가 + 예상 수익(리스크 금액 × 손익비). 현재 입력한 손익비 행은 하이라이트.
2. **연속 익절/손절 복리 시뮬레이션** (엑셀 E11:I21) — 10회차. 엑셀은 5%·1.5 하드코딩이지만 코드는 입력값 기준으로 일반화(`w = w + w*risk*rr`, `l = l*(1-risk)`). 기본값에서 엑셀과 수치 완전 일치(10회 익절 206.1032 / 10회 손절 59.8737).
3. **용어 정리**: `권장 배율` → `이론 배율` 전역 치환(컴포넌트 라벨, `page.tsx` SEO 본문, `calculatorPages.ts`, `constants.ts`) + "거래소 최대 배율을 넘을 수 있으니 실제 진입은 더 낮게" 안내문 추가.

## 의도적으로 넣지 않은 것

- 엑셀의 리스크 5/4/3/20% 프리셋 수량표 → 리스크 비율을 이미 자유 입력받으므로 중복.
- 숏 포지션 지원 → `stop >= entry` 무효 처리 유지. 원본 엑셀도 롱 전용 구조라 복제 기준으로는 정상.

## 모바일/하이라이트 수정 (같은 날 2차)

리뷰에서 확인된 2건 수정:

1. **현재 손익비 하이라이트 누락** — `RR_STEPS`가 `1.1, 2 … 10`뿐이라 기본값 1.5가 표에 없었음.
   `Array.from(new Set([...RR_STEPS, rr])).sort()`로 현재 입력한 손익비를 정렬 위치에 병합.
   이제 `1 : 1.5` 행이 1.1과 2 사이에 생기고 강조됨.
2. **모바일 390px 가로 넘침(약 88px)** — 원인은 표가 아니라 `CalculatorLayout`의 그리드.
   `grid gap-6`의 단일 컬럼 트랙이 `min-width: auto`라, 표 카드의 `min-w-[420px]`가 트랙 전체를 밀어
   입력 카드까지 같이 넘쳤음. `grid-cols-[minmax(0,1fr)]`로 트랙을 고정(`Shared.tsx`, 전 계산기 공통 적용)하고
   표 카드에 `min-w-0`, 표 최소폭 420px → 300px로 축소.
   검증: 390px 뷰포트에서 `documentElement.scrollWidth - clientWidth = 0`, 넘침 요소 0개, 표 내부 가로 스크롤도 없음.

부가: 표 숫자를 `formatFixed`(소수점 2자리 고정)로 통일해 세로 정렬을 맞춤.
화면 표기는 `206.10` / `59.87`이며, 내부 계산은 전체 정밀도(`206.1032…` / `59.8737…`)로 수행됨.

검증: `tsc --noEmit`, `eslint` 통과 + 로컬 dev 서버 390px 실측.
